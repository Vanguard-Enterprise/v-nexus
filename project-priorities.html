Vanguard Nexus priorities

A Rust control panel for apps, clusters, and servers. A growing list of ideas, with short examples.

Priority 1 · Foundation

  • Rust core. Build the server, CLI, and agents in Rust.Example: one shared API for the panel and CLI.
  • Config-file setup and settings. Use a validated, versioned config file for platform settings.Example: configure auth, database access, and alerts in YAML; mount through a ConfigMap later.
  • Configuration ownership. Make file-managed settings clear in the dashboard.Example: show where to change a setting and whether it needs a restart.
  • Configuration validation. Catch invalid settings and missing dependencies before saving or applying changes.Example: flag a missing secret reference before deploying an app.
  • Database design. Decide where configuration, jobs, history, and agent state live.Example: evaluate PostgreSQL for the server and local agent persistence; plan migrations and recovery.
  • Installation packaging. Start with containers and plain Kubernetes manifests.Example: mount the config file directly; add a Helm chart once configuration settles.
  • Easy setup. Install the panel on a server or cluster using a config file.Example: start the server with database and identity-provider settings supplied.
  • Projects and environments. Group apps, access, and settings.Example: one project with staging and production.
  • Authentication and permissions. Connect OIDC and control access.Example: Zitadel login with project operator roles.
  • API and events. Let future tools manage apps through scoped access.Example: another app requests a new environment.

Priority 2 · First usable version

  • Infrastructure inventory. Search servers, clusters, apps, domains, and volumes in one view.Example: find every resource belonging to a production project.
  • Saved views. Save frequently used filters for quick access.Example: open a view of production issues or servers at home.
  • Application ownership. Assign maintainers and contact details to services.Example: find who owns an app when an alert fires.
  • Kubernetes clusters. Connect existing clusters through an agent.Example: manage a remote cluster from the same panel.
  • Docker hosts. Deploy containers and supported Compose stacks.Example: run an app and Redis on a VPS.
  • Linux servers. Monitor hosts and manage enabled services.Example: check disk space or restart a systemd service.
  • Agent enrollment. Securely register and revoke machines.Example: join with an expiring token and connect outbound.
  • Connection recovery. Keep apps running if the panel disconnects.Example: reconnect and report pending task results.
  • App deployment. Deploy an image or build from a repository.Example: publish a Git commit to staging.
  • Domains and TLS. Route traffic and manage certificates.Example: attach app.example.com with HTTPS.
  • Configuration and secrets. Manage app settings and secret references.Example: inject a database credential from OpenBao.
  • Persistent storage. Configure volumes for application data.Example: preserve uploads between deployments.
  • Health and logs. Show app status, events, and deployment history.Example: inspect why a container keeps restarting.
  • Alerts. Notify on failures with deduplication and maintenance windows.Example: alert when an agent disconnects or a disk fills up.
  • Audit history. Record changes and who requested them.Example: trace a production update to its approval.
  • Maintenance mode. Pause deployments, automatic updates, and selected alerts during planned work.Example: put a cluster into maintenance before upgrading its nodes.
  • Change previews. Show planned changes and affected dependencies before applying them.Example: review which services a storage change could affect.
  • Disaster recovery. Back up the panel's configuration and state, with a documented recovery process.Example: restore management on a replacement server after losing its host.
  • Release recovery. Restore an earlier app version when safe.Example: abort a failed canary; handle database recovery separately.

Priority 3 · Delivery and management

  • Storage growth forecasts. Estimate when volumes may fill up from recent usage.Example: warn that an uploads volume could run out of space next week.
  • Integration health. Show disconnected providers, expired credentials, and missing permissions.Example: identify why a DNS integration can no longer update records.
  • Infrastructure import. Discover existing workloads and choose monitoring or explicit management.Example: inspect an existing app before handing control to the panel.
  • Connectivity diagnostics. Check DNS, routes, ports, and VPN reachability to investigate connection failures.Example: explain why an app cannot reach a database at another site.
  • Site overview. Group infrastructure by location with health, capacity, and connection status.Example: spot an offline site and its affected services at a glance.
  • Upgrade compatibility checks. Check known version requirements across connected systems before upgrading.Example: flag a Kubernetes upgrade that conflicts with a storage provider's supported versions.
  • Incident timeline. Show a simple overview of alerts, deployments, and changes, with optional interactive detail.Example: see the outage time and recent changes first, then expand events, logs, and filters.
  • Network and VPN management. Prioritize connections to NetBird, Tailscale, and custom VPNs for multi-site infrastructure.Example: view peers, site connectivity, routes, and supported access rules through provider integrations.
  • Secret rotation. Track credential renewal and coordinate changes across affected apps.Example: rotate a database credential and update its consumers.
  • Runbooks. Save repeatable maintenance procedures with approvals and execution logs.Example: drain a node, reboot it, and verify health before continuing.
  • Service health checks. Test endpoints and ports beyond container health.Example: alert when an app's HTTP endpoint fails while its container is running.
  • Dependency map. Show relationships between apps and their supporting services.Example: see which apps depend on a database before restarting it.
  • Certificate management. Integrate with cert-manager and other certificate providers to track issuance, renewal, and expiry.Example: identify a failed renewal and inspect its status from the dashboard.
  • DNS management. Manage records through connected DNS providers.Example: create an app's DNS record during deployment.
  • Resource management. Track CPU, memory, and storage usage alongside capacity and limits.Example: find room for a new app or adjust an existing app's limits.
  • Scheduled jobs. Manage recurring tasks with execution history and failure alerts.Example: run nightly cleanup and report a failed execution.
  • Configuration comparison. Compare environments and highlight differences without exposing secret values.Example: spot different images or missing secret references between staging and production.
  • Temporary access. Grant scoped access with automatic expiry and an audit trail.Example: give an operator access to a project for two hours.
  • Reusable blueprints. Save common application setups with configurable values.Example: deploy a standard web app with its database and domain settings.
  • Talos Linux integration. Plan API-based node health, machine configuration, upgrades, and maintenance.Example: review a Talos configuration change and upgrade nodes in stages with health checks.
  • Build workers. Build images away from the management server.Example: build a Dockerfile and push to a registry.
  • GitOps. Sync declared configuration and detect drift.Example: flag a manual change to a managed deployment.
  • Progressive rollouts. Support canary and blue-green where available.Example: send 10% of traffic to a new version.
  • Promotion and approvals. Move a tested release between environments.Example: approve the staging image for production.
  • Storage provider integrations. Manage supported storage through provider APIs in the dashboard.Example: inspect Longhorn volumes, capacity, and snapshots without switching tools.
  • AI access. Expose diagnostics and approved actions through MCP.Example: explain a failed release and propose a repair.

Priority 4 · Future ideas

  • Failure rehearsals. Simulate unavailable services or disconnected sites to test recovery.Example: run a controlled outage exercise in a test environment.
  • Application relocation. Guide moving apps between hosts or clusters, including data and traffic cutover.Example: move a service to another site after verifying its copied data.
  • Network lockout protection. Arrange automatic reverts for supported network changes unless connectivity is confirmed.Example: revert a VPN route change if the management connection is lost.
  • Incident replay. Reconstruct recorded configuration, versions, and events around an outage.Example: review the deployed image and configuration changes preceding a failure.
  • Offline recovery kit. Export encrypted essential configuration and recovery instructions.Example: recover management when both the panel and identity provider are unavailable.
  • Enterprise chaos testing. Explore optional integrations with Chaos Monkey or other failure-injection tools for resilience tests and team exercises.Example: approve a scoped experiment with time limits, stop controls, and recovery checks.
  • Orphan detection. Find unused resources for review before cleanup.Example: flag unattached volumes, stale DNS records, and abandoned preview environments.
  • Dynamic DNS. Explore built-in DDNS updates or integrations with existing services.Example: update a hostname when a server's public IP changes.
  • Update discovery. Periodically check tracked registries and GitHub releases or delivery repositories.Example: compare a deployed NetBird image with a newer allowed version or changed tag digest.
  • Upgrade notifications. Offer an upgrade through Slack, Discord, email, or the dashboard.Example: send a NetBird update notice with release notes and a link to approve.
  • Automatic update policies. Choose notify-only, approval-required, or automatic updates per app.Example: update staging automatically during a maintenance window after health checks.
  • Git-aware updates. Keep upgrade actions consistent with the deployment source.Example: propose a Git change for managed apps; update a directly managed app through its agent.
  • Preview environments. Create temporary apps for pull requests.Example: remove the preview when the PR closes.
  • Backups and restores. Schedule supported backups and test recovery.Example: restore an app database from last night's backup.
  • Backup verification. Automatically test restores in isolation and report failures.Example: restore a database backup into a temporary environment and check it works.
  • Fleet releases. Deploy across selected targets in stages.Example: update a test cluster before production clusters.
  • Cluster provisioning. Create and upgrade supported clusters.Example: prepare Linux machines for a new cluster.
Working ideas, grouped by suggested priority. Scope and order can change as we plan.
